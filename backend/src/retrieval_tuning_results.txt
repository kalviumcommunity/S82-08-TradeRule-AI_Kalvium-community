7. JUSTIFICATION
----------------

baseline_k3 was selected because it achieved the same perfect measured
retrieval relevance as the stricter configuration while retrieving only
three chunks.

Using three chunks keeps the context smaller and avoids passing unnecessary
retrieved content to the downstream LLM.

The strict k=5 configuration with a 0.72 score threshold did not provide
any measured improvement on the current test queries.


8. KEY OBSERVATION
------------------

The biggest measured effect in this experiment came from the score
threshold reducing the number of returned chunks rather than improving
retrieval accuracy.

Both configurations successfully placed the expected source at rank 1
for all three queries.


9. LIMITATION
-------------

The evaluation contains only three synthetic test queries and a small
corpus. Therefore, the results demonstrate that the current retrieval
configuration works well for these test cases, but they do not prove that
the selected configuration is optimal for all future TradeRule AI queries.
