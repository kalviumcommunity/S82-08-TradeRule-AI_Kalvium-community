TASK 3 — REUSE ACROSS TWO FEATURES
======================================================================

Feature 1:

backend/src/template_chat.py

Purpose:
Builds prompts for the chat/CLI path.


Feature 2:

backend/src/template_batch.py

Purpose:
Builds prompts for the batch evaluation path.


Both features import:

from prompts.answer import ANSWER_TEMPLATE, render


Both features use the same:

ANSWER_TEMPLATE


Therefore, the prompt wording is defined only once.


======================================================================
TASK 4 — PROMPTS SEPARATED FROM BUSINESS LOGIC
======================================================================

Prompt module:

prompts/answer.py


Business/feature modules:

backend/src/template_chat.py
backend/src/template_batch.py


The feature modules do not contain duplicated copies
of the main prompt.

If the prompt wording needs to change, the central
template can be updated in:

prompts/answer.py


The feature implementations do not need to be modified
when only the prompt wording changes.

======================================================================
VERSIONING / MAINTENANCE
======================================================================

The reusable template is stored in Git as a normal source file.

A future prompt change can be made in:

prompts/answer.py

For example:

Version 1:
Answer ONLY from the provided context.

Version 2:
Answer ONLY from the provided context and explicitly
identify which context statement supports the answer.

The change can then be reviewed through a normal Git
diff and pull request before being used by all features.
